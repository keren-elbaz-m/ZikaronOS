# Phase 2 — Shared logic and data

Tasks: T4, T5, T6, T7 · ACs: AC9, AC10, AC13 (and the contracts every later phase uses)

Read first: `prototype/zikaron-next/lib/types.ts`, `lib/data.ts`, `lib/utils.ts`, `lib/store.tsx` (the prototype's rules live there), and the prototype README table.

## Steps

1. `packages/contracts` (zod 4):
   - Enums: roles (see 00-conventions), audiences, slots, witness types/statuses, accessibility, special populations, programs, archive reasons, registration status.
   - Phone rule with `libphonenumber-js/max` (strict, Israeli + international, same as prototype); exported `phoneSchema`.
   - Schemas for every request/response named in spec → Technical Approach (auth, salons, map DTO without host contacts, reference, registrations, host salons, admin lists/details, teaming match with reasons, assignments, notes, exports, search, dashboard KPIs). Export inferred types.
   - Tests: phone valid/invalid examples, map DTO has no `phone`/`email`.
2. `packages/domain` — pure functions, no I/O, **test-first**:
   - `slotOf(time)` with the one rule; boundaries 07:59/08:00/11:59/12:00/16:59/17:00/23:59.
   - Capacity: `seatsLeft(salon, registrations)`, `canRegister(salon, guest, seats)` (1–3 seats, open for guests, not past, one active registration per guest — a new one replaces the old, as legacy), returning typed reasons.
   - Teaming: `scoreMatch(salon, witness, context)` → `{ score, reasons: {dateSlot, language, distance, accessibility, yearlyLoad}: ok|fail + detail }`, `rankMatches(...)`; haversine distance. Port the prototype's scoring so results match it.
   - Witness availability and status rules from the prototype (status changes blocked while assigned).
3. `packages/db` (Prisma, Postgres):
   - Schema: `User` (email unique, passwordHash, role, name, phone, locale), `Host`, `Salon` (this season's salon event; fields from prototype `Salon`), `Registration` (guest user ↔ salon, seats, status), `Witness`, `WitnessAvailability` (date × slot), `Assignment` (salon ↔ witness, assignedBy, createdAt), `SalonDay`, `City`, `Country`, `Community`, `Language`, `Training`, `Note` (entity type + id, author, text), `HostHistory`, `OutboxEvent` (id, type, payload json, createdAt, dispatchedAt null), `JobFailure`.
   - Uses `timestamptz`. Indexes on foreign keys and on `OutboxEvent(dispatchedAt)`.
   - `src/client.ts` exports a singleton `PrismaClient`; `src/outbox.ts` exports `withOutbox(tx, { type, payload })`.
   - Scripts: `db:migrate` (`prisma migrate dev`/`deploy`), `db:seed`, `db:reset` (`prisma migrate reset --force` + seed).
4. Seed (`packages/db/prisma/seed.ts`): convert `prototype/zikaron-next/lib/data.ts` (copy the data into the seed; do not import from the prototype at runtime). Create one user per role: `<role>@zikaron.local` / password `Zikaron!2026` (local-dev-only, documented in `.env.example` comments). Reseeding is idempotent.

## Decisions

- **D1 Prisma 7.10.1, not the npm `latest` tag.** `prisma@latest` is `8.0.0-rc.34`, a release candidate, so we pin the stable 7.10.1 (with `@prisma/client` and `@prisma/adapter-pg` at the same version, and `pg` 8.23.1).
  - Prisma 7 has no URL in the schema. `prisma.config.ts` reads `DATABASE_URL` without a fallback, so migrate fails loudly without it, but `prisma generate` still works with no database.
  - The client needs a driver adapter: `new PrismaClient({ adapter: new PrismaPg({ connectionString }) })`.
  - The generator is `prisma-client` (ESM, `.js` import extensions). Its output goes to `src/generated/prisma`, which is git-ignored and regenerated by `build` and `typecheck`.
- **D2 Partial unique index via the `partialIndexes` preview feature.** It is `@@unique([guestUserId], where: raw("status = 'active'"))`, named `Registration_one_active_per_guest`. The database enforces "one active registration per guest" even under concurrent requests, and `migrate dev` stays in sync with no hand-written SQL.
- **D3 Salon time is one `startsAt timestamptz`.** There are no separate date or time columns. `@zikaron/domain` has `salonStartsAt(date, time)` and `jerusalemParts(instant)` to convert to and from Asia/Jerusalem wall-clock time, with DST handled through `Intl`. Contracts keep `date` + `time` + `slot` in the DTOs. Calendar-only values (salon days, birth dates, host history) are `@db.Date`.
- **D4 Languages are ISO-639-1 codes.** `Language(code, name)` stores the language's own name, so `"עברית"` becomes `he`. Salons have `languageCode`, and witnesses have an implicit many-to-many to `Language`. `Deutsch` (`de`) is added because witness w1 speaks it but the prototype's `LANGUAGES` list lacks it. The result is 7 languages.
- **D5 Reference data is bilingual where it is product text.** This covers `City.nameHe/nameEn` and `SalonDay.labelHe/labelEn`. Other fields are added as follows:
  - `Country(code, nameHe, nameEn)` with 11 rows, covering the prototype's three countries of birth plus common ones.
  - `Community(id, name)` with slug ids.
  - `Training.startsAt` as a timestamptz.
  - `season` (2027) on `Salon`, `SalonDay` and `Training`.
- **D6 Seeded password is `Zikaron-local-dev-1`, not `Zikaron!2026`.**
  - Phase 1 had already documented `Zikaron-local-dev-1` in `.env.example`, and agents may not edit `.env*` files. So the code (`SEED_USER_PASSWORD` in `packages/db/src/seed/run.ts`) matches what is documented.
  - Logins are `<role>@zikaron.local` for all 8 roles. `host@zikaron.local` is linked to prototype host h1 (נועה כהן, salon s1).
  - Each of the 7 prototype registrations becomes a guest user with the same password (for example `ori@example.com`). That makes 15 users.
- **D7 Passwords use argon2id via `@node-rs/argon2`** (prebuilt binaries, no node-gyp), stored as PHC strings starting with `$argon2id$`. Phase 3's `@zikaron/auth` must verify with an argon2id library. `@node-rs/argon2` `verify` works directly.
- **D8 Prototype data is copied verbatim** into `packages/db/src/seed/prototype-{data,types}.ts`, where only the import path changes. A pure, unit-tested converter (`convert.ts`) turns it into rows. Deliberate normalisations:
  - Salon `email` comes from its host, because the prototype gives every salon the placeholder `host@example.com`.
  - `""` becomes `null`.
  - The prototype's local datetimes are read as Asia/Jerusalem.
  - Witnesses without `createdAt` get the fixed date `2027-01-01` (Jerusalem) so the seed stays reproducible.
- **D9 The seed is idempotent through upserts on fixed ids**, all in one transaction. Availability for seeded witnesses is replaced each run. It prints a seed-vs-db table and exits 1 only if seed rows are missing. Extra rows that the app created are reported, not deleted.
- **D10 `db:migrate` is `prisma migrate deploy`.** It is non-interactive, so it suits `setup:local`. New migrations are authored with `pnpm --filter @zikaron/db db:migrate:dev`. `db:reset` is `prisma migrate reset --force && tsx prisma/seed.ts`. Prisma 7 does not seed on reset, so the seed is explicit and `prisma.config.ts` has no `seed` entry.
- **D11 The client is lazy, with no import-time singleton.** `getPrisma(env = process.env)` creates the shared client on first use and throws `Missing env: DATABASE_URL`. `createPrismaClient(url)` is for Nest `PrismaService`, and `disconnectPrisma()` is also provided. Importing `@zikaron/db` never needs a database.
- **D12 Domain results carry data, not text.** Teaming reasons are `{ ok, detail }` with typed details. Rejections are string codes defined in contracts:
  - `REGISTRATION_REJECTIONS`
  - `ASSIGNMENT_REJECTIONS`
  - `WITNESS_CHANGE_REJECTIONS`

  The UI translates them, as required by AC4. Teaming also has a `status` reason (witness not "available" this year), as in the prototype, in addition to the five AC10 reasons.
- **D13 `canRegister` lists every failing reason.** `not_enough_seats` is checked only when the other checks pass. The guest's own active registration is excluded from the seats taken, which makes it the "replace the old one" rule (returned as `replaces`), and the same function serves PATCH seat changes.
- **D14 Geocoding mock in domain.** `mockGeocode(city, address)` returns the city centre plus a deterministic offset of at most ±0.01°, using an FNV-1a hash and no network. `addressCityConflict(address, cityId, cities)` ports the wizard rule "the address must belong to the chosen city", checking both he and en names.
- **D15 Public DTOs omit host contacts and the street address.** `salonMapItemSchema` and `salonPublicSchema` have no phone, email, address, floor or apartment. The prototype sends the full address only to registered guests, through `registeredSalonSchema` in `GET /me/registration`. `z.object` strips unknown keys, so passing a full row does not leak them.
- **D16 Phone rule.** `phoneSchema` normalises to E.164, and its error message is the code `invalid_phone`. Passwords must be at least 10 characters (`PASSWORD_MIN_LENGTH`). Emails are trimmed and lower-cased.
- **D17 Packages and dependencies.**
  - `@zikaron/contracts` depends on zod and libphonenumber-js.
  - `@zikaron/domain` depends only on `@zikaron/contracts` (for types and constants).
  - `@zikaron/db` depends on contracts and domain (for `withOutbox` type validation and seed time conversion) and on `@node-rs/argon2`.
  - `@zikaron/db` exports `.` (client, Prisma types and enums, `withOutbox`) and `./seed` (`seed`, `buildSeed`, `hashPassword`, `SEED_USER_PASSWORD`, …).
  - All three are ESM built to `dist`, and `require()` from CJS works (verified).

**Phase 3 must know:**
- Import shapes from `@zikaron/contracts`, rules from `@zikaron/domain`, and `getPrisma`/`createPrismaClient`, `withOutbox`, and Prisma types and enums from `@zikaron/db`. Rows are converted to DTOs in the API: `startsAt` becomes `date`/`time` via `jerusalemParts`, and `slot` comes from `slotOf`.
- **Registrations.** Load the salon and the guest's active registration, then call `canRegister`. If `replaces` is set, mark that registration `cancelled` (with `cancelledAt`) **before** creating the new one, in the same transaction, together with `withOutbox(tx, { type: "registration.created", … })`. Otherwise the partial unique index throws (Prisma error `P2002`), which you should also map to a 409.
- **Integration tests.** Use `TEST_DATABASE_URL`. Do not use `prisma migrate reset` in tests, because the same AI guard blocks it. Use `migrate deploy` (see `packages/db/src/test/global-setup.ts`) and clean up with deletes or TRUNCATE. To get demo data into the test database, call `seed(createPrismaClient(TEST_DATABASE_URL))` from `@zikaron/db/seed`.
- **Passwords** are argon2id PHC strings, and the seeded password is `Zikaron-local-dev-1`. `PASSWORD_MIN_LENGTH` is 10.
- **Outbox types** are limited to `OUTBOX_EVENT_TYPES`. Add new ones there, additively, and `withOutbox` will accept them.
- `Salon.hostName/phone/email/orgName` are denormalised copies of `Host`. Keep them in sync when the host changes, as the prototype's `updateHost` did.
- Witness self-registration is dropped. Staff create witnesses through `witnessCreateRequestSchema`.
